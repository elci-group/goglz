  "content": "# Goglz\n\n<p align=\"center\">\n  <picture>\n    <source media=\"(prefers-color-scheme: dark)\"\n            srcset=\"assets/logo-dark.svg\">\n    <img src=\"assets/logo-light.svg\" alt=\"Goglz\" width=\"96\" height=\"96\">\n  </picture>\n</p>\n\nGoglz is an intelligent document‑monitoring daemon written in Rust. It watches\nspecified directories, analyzes documents with state‑of‑the‑art AI models, and\nproduces clearer versions.\n\n## Overview\n\nGoglz runs as a background service that continuously monitors your document\nrepositories. When a file is created or modified, it automatically:\n\n1. **Conceptualizes** the content with the GPT‑OSS 120B model to extract a\n   summary, key concepts, and themes.\n2. **Improves clarity** using LLaMA models via the Groq API.\n3. **Structures output** as JSON metadata and an improved‑text file.\n\n## Key Features\n\n### Intelligent Monitoring\n- **Multi‑directory support** – monitor several directories with independent\n  configurations.\n- **Pattern matching** – filter files by glob patterns (e.g., `*.txt`, `*.md`).\n- **Recursive watching** – include sub‑directories when enabled.\n- **Debouncing** – delay processing while a file is actively edited.\n\n### AI‑Powered Analysis\n- **GPT‑OSS 120B** – deep conceptualization for comprehensive understanding.\n- **GPT‑OSS 20B** – focused clarity improvement.\n- **LLaMA via Groq** – fast inference with open‑source models.\n- **Structured output** – consistent JSON with summary, concepts, themes, and\n  clarity scores.\n\n### Production‑Ready Daemon\n- **Background operation** – runs as a system daemon with proper PID handling.\n- **Robust error handling** – graceful degradation and detailed reports.\n- **Configurable processing** – control file‑size limits, batch sizes, and\n  timing parameters.\n- **Clean shutdown** – handles termination signals for a tidy exit.\n\n## Installation\n\n### From Source\n\n```bash\n# Clone the repository\ngit clone https://github.com/elci-group/goglz.git\ncd goglz\n\n# Build in release mode\ncargo build --release\n\n# Binary is located at target/release/goglz\n```\n\n### Using Baby\n\n```bash\nbaby install goglz\n```\n\n## Configuration\n\n### Initial Setup\n\nGoglz stores its configuration in a TOML file at `~/.goglz`. Create the file\nwith:\n\n```bash\ngoglz init-config\n```\n\n### Configuration Structure\n\n```toml\n# Directories to monitor\n[[directories]]\npath = \"~/Documents\"\nfile_patterns = [\"*.txt\", \"*.md\", \"*.rst\"]\nrecursive = true\n\n[[directories]]\npath = \"~/Notes\"\nfile_patterns = [\"*.md\"]\nrecursive = true\n\n# GPT‑OSS configuration (conceptualization)\n[gpt_oss]\napi_endpoint = \"https://api.gpt-oss.com/v1\"\napi_key = \"your-gpt-oss-api-key\"\nmodel_120b = \"gpt-oss-120b\"\nmodel_20b = \"gpt-oss-20b\"\n\n# Groq configuration (LLaMA inference)\n[groq]\napi_key = \"your-groq-api-key\"\nmodel = \"llama3-70b-8192\"\napi_endpoint = \"https://api.groq.com/openai/v1\"\n\n# Processing settings\n[processing]\noutput_directory = \"~/.goglz_output\"\nmax_file_size_mb = 10\nbatch_size = 5\ndebounce_interval_ms = 2000\n```\n\n### Configuration Options\n\n#### Directories\n- `path` – directory to monitor (supports `~` expansion).\n- `file_patterns` – array of glob patterns for file matching.\n- `recursive` – `true` to watch sub‑directories.\n\n#### GPT‑OSS\n- `api_endpoint` – base URL for the GPT‑OSS API.\n- `api_key` – your GPT‑OSS credential.\n- `model_120b` – identifier for the 120B‑parameter model.\n- `model_20b` – identifier for the 20B‑parameter model.\n\n#### Groq\n- `api_key` – your Groq credential.\n- `model` – LLaMA model to use (e.g., `llama3-70b-8192`).\n- `api_endpoint` – base URL for the Groq API.\n\n#### Processing\n- `output_directory` – where processed results are saved.\n- `max_file_size_mb` – maximum file size to process.\n- `batch_size` – number of files processed concurrently.\n- `debounce_interval_ms` – delay before processing changed files.\n\n## Usage\n\n### Starting the Daemon\n\n#### Background Mode (recommended)\n\n```bash\ngoglz start\n```\n\n#### Foreground Mode (debugging)\n\n```bash\ngoglz start --foreground\n```\n\n### Managing the Daemon\n\n```bash\n# Show daemon status\ngoglz status\n\n# Stop the daemon\ngoglz stop\n\n# Re‑initialize configuration\ngoglz init-config\n```\n\n## Portfolio Mode\n\nGoglz can operate across every project that contains a `goglz.yaml` file under\nyour home directory. Use the `--portfolio` flag to enable this mode.\n\n### Supported Commands\n\n- `goglz --portfolio revise` – revise documents in all detected projects.\n- `goglz --portfolio start` – start the daemon for all detected projects.\n\nCommands that do not act on a specific directory (`stop`, `status`,\n`init-config`) accept `--portfolio` but issue a warning because the flag has\nno effect.\n\n### Project Discovery Rules\n\n- Search up to four directory levels deep under `$HOME`.\n- Ignore hidden directories (names beginning with `.`).\n- Load each project's own `goglz.yaml` when running `revise`.\n- `start --portfolio` watches each project recursively for `*.md`, `*.txt`,\n  and `*.rst` files.\n\n### Examples\n\n```bash\n# Revise all documents across every Goglz project in $HOME\ngoglz --portfolio revise\n\n# Start the daemon for every detected project\ngoglz --portfolio start\n```\n\n## Processing Pipeline\n\n### Workflow\n\n1. **File detection** – monitor reports creation or modification events.\n2. **Debouncing** – wait the configured interval to avoid processing active edits.\n3. **Content analysis**\n   - Read the file (subject to size limits).\n   - Send content to GPT‑OSS 120B for conceptualization.\n   - Send content to LLaMA via Groq for clarity improvement.\n4. **Result generation** – create structured output with metadata and improved\n   text.\n5. **Output storage** – write results to the configured output directory.\n\n### Output Format\n\nEach processed file yields two artifacts:\n\n#### JSON Result (`<filename>_<uuid>.json`)\n\n```json\n{\n  \"id\": \"unique-identifier\",\n  \"file_path\": \"/path/to/original/file\",\n  \"timestamp\": \"2024-01-01T00:00:00Z\",\n  \"conceptualization\": {\n    \"summary\": \"Concise document summary\",\n    \"key_concepts\": [\"concept1\", \"concept2\"],\n    \"themes\": [\"theme1\", \"theme2\"],\n    \"clarity_score\": 0.75\n  },
